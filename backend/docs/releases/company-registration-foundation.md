# Company registration — submission and review foundation

Source: existing four company registration design screens, existing SMS verification and ten-digit tracking contracts.
This increment adds a distinct company application, additive persistence migration, multipart submission and verified-mobile status lookup. Codes are unique within the company application namespace; tracking explicitly distinguishes company and startup. A successful submission creates only pending_review and a durable submission SMS notice. It does not create an Organization, user, tax certificate or approved status.
The API is disabled by default (CompanyRegistration:Enabled) and also requires existing SMS verification to be enabled. The public four-step UI uses the real API and remains unavailable until the feature is enabled.
The four designed supporting documents are stored as restricted application evidence, not published. The 10 MB limit applies separately to the representative letter and collectively to the three company documents, based on the existing screen text. Signature validation is not malware scanning or official registry verification. Field lengths are technical bounds, not official tax or corporate criteria. The public form, restricted evidence access, and account activation now follow the separate company-application-review.md contract. Company approval belongs to active system_admin identities; no official legal/tax eligibility is assumed.
No production migration or enablement is authorized by this draft.
