The existing system-admin authorization policy is a technical prerequisite; it does not designate who is authorized to approve company registration. No approval rule is inferred. All reads additionally require an active persisted identity, CompanyRegistration:ReviewEnabled=true and an explicit ReviewerSubjects allowlist. The default is disabled. List/detail/document read access is audited; details and attachment responses are no-store; documents download as attachments; no public attachment route. No production configuration has been changed. The owner must designate the review/approval authority and confirm account activation and duplicate-company rules before enabling review or implementing approval. No tax/legal certification or account creation occurs in this increment.

Company registration approval belongs exclusively to the Moon system administrator (system_admin); startup authority is unchanged. Approval requires an explicit human confirmation, the existing active-admin/allowlist review gate and separately enabled ApprovalEnabled. Account provisioning uses the existing company role and organization type, with a disabled SMS-only Keycloak account, then committed pending activation and verified lineage before enabling. Only committed approved enqueues template 833279.
