# Company application review and approval

All review reads require an active persisted system_admin identity, ReviewEnabled=true. List/detail/document reads are audited; detail and attachment responses are no-store; documents download as attachments. No public attachment route.

## Owner decision — 2026-11-27
Company registration approval belongs exclusively to the Moon system administrator (system_admin); startup authority is unchanged. Approval requires an explicit human confirmation, the existing active-admin role review gate and separately enabled ApprovalEnabled. Account provisioning uses the existing company role and organization type, with a disabled SMS-only Keycloak account, then committed pending activation and verified lineage before enabling. Only committed approved enqueues template 833279. No automatic identity merging: conflicts are blocked for operator review; orphaned disabled accounts from uncertain Keycloak create acknowledgements require reconciliation, never automatic adoption. Existing companies without an application-linked national identifier cannot be automatically matched. This is a conservative technical conflict guard, not a new business eligibility or tax rule. The feature remains off until explicit production configuration and end-to-end acceptance. Migration is additive; no data reset.

## Activation safety and deployment configuration
Pending activation persists an inactive Moon user and membership and a pending_activation organization. Keycloak enable is followed by a single transaction activating all three, recording approved and enqueueing the notice. Failed or uncertain enable is retried against the exact persisted subject; Moon access remains inactive until commit. A disabled orphan after uncertain create still requires operator reconciliation. Deployment flags CompanyRegistration__Enabled, CompanyRegistration__ReviewEnabled and CompanyRegistration__ApprovalEnabled default false. No fixed administrator subject or per-user deployment setting is required. No credentials are assumed. Direct account activation does not issue Article 172 certificates. Documents are structurally validated, not malware-scanned; external registry/eligibility checks are not implemented.

## Owner amendment — role-based authority
The owner removed the per-subject allowlist on 2026-11-27. Any active persisted Moon identity with the authenticated system_admin role can review when enabled and explicitly approve when ApprovalEnabled is also enabled. The existing system-admin endpoint authorization remains mandatory. No other role gains this access. Administrator account and role lifecycle management belongs to the subsequent admin panel work; it must preserve at least one active administrator, use OTP, preserve audit/financial history, and must not depend on a fixed UUID or require a server configuration change for an administrator replacement. This amendment does not implement administrator provisioning or change existing admin management endpoints.
