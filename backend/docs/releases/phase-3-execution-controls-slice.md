Status: **CLOSED / GREEN** for this slice only.

Overall Phase 3 status: **OPEN** pending final Phase 3/platform acceptance. This closure does not authorize a merge to `main`.

## Scope delivered

This slice extends the already-green execution/reporting flow with:

- execution expense submission and finance review;
- execution risk reporting, mitigation, and closure;
- project execution freeze/unfreeze controls;
- staged disbursement limits on execution stages;
- staged disbursement accounting through the immutable double-entry ledger;
- audit coverage for execution-control transitions;
- transactional outbox emission for staged disbursement release;
- persistence guards for immutable/final execution-control state.

## Authorization and blocking rules

- Expense submitter is resolved from active DB-backed organization membership for the project.
- Expense review requires the `finance` role.
- Risk management requires the `supervisor` role.
- Freeze/unfreeze requires the `supervisor` role.
- Staged disbursement requires the `finance` role.
- Freeze is enforced in the backend and blocks progress-report submit/review, expense submit/review, and staged disbursement.
- Risk reporting/management remains available while frozen so the reason for a freeze can be remediated.
- A stage report cannot be approved while that stage has an expense still awaiting finance review.
- Staged disbursement is allowed only for the active stage.
- Stage disbursement cap/currency are immutable execution-stage terms after execution starts.

## Financial integrity

No parallel project-balance source was introduced.

Allocable project balance continues to be derived only from the ledger. A staged disbursement posts an immutable balanced journal:

- debit: `liability:project_funds`
- credit: `liability:disbursement_payable`

The journal kind is `stage_disbursement`. `LedgerJournal.PaymentId` is nullable for non-payment journals, and staged disbursement journals are linked by `ExecutionDisbursementId`.

Corrections continue to use the existing reversal-journal mechanism. Reversed staged-disbursement journals restore both ledger allocable balance and stage release capacity; destructive mutation is not allowed.

`ExecutionDisbursementReleased` is written through the existing PostgreSQL transactional outbox.
